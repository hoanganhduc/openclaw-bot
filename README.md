# openclaw-bot

> ⚠️ **Generated by an AI coding system — experimental.** Every file in this
> repository — code, configuration, and documentation — was written by the same
> multi-agent AI coding system it helps rebuild. It is **experimental**, built for one
> researcher's personal setup, and **may not work as expected** on other machines,
> other OpenClaw versions, or tasks outside the documented assumptions.

Manifest-driven rebuild for the **OpenClaw** research-assistant bot: sanitized config
templates, workspace skills, and lifecycle scripts. It is the OpenClaw component of the
larger [**coding-system-rebuild**](https://github.com/hoanganhduc/coding-system-rebuild)
backup/restore system, which pins and invokes it.

## What's here

- **`REBUILD-MANIFEST.json`** — allowlist manifest classifying every OpenClaw config,
  workspace skill, agent bootstrap dir, systemd unit, and cron job as
  `public-copy` / `public-template` / `private-archive` / `exclude-*`.
- **Lifecycle scripts** — `sync.sh` (live system → sanitized templates), `install.sh`,
  `backup.sh`, `restore.sh`, `deploy.sh`, `test-roundtrip.sh`.
- **Sanitized artifacts** under `config/`, `workspace/`, `systemd/`, … —
  generated by `sync.sh --apply` with secrets redacted, personal IDs masked, and paths
  templated to `{{ USER_HOME }}` / `{{ OPENCLAW_HOME }}`.

Per-agent `models.json` and `auth-profiles.json` are deliberately absent from
the public component. OpenClaw accepts redaction placeholders as credential
strings, so installing those files would create a false-positive auth source.
Endpoint/model configuration comes from `openclaw.json`; owner-private agent
state is restored separately.

## Use

This component is normally driven by the umbrella system (`make install` there clones and
runs it). Standalone:

```bash
./install.sh --prefix "$HOME/.openclaw" --skip-docker --skip-services --skip-config
```

See the umbrella repo's docs for the full picture, and the
[introductory blog post](https://hoanganhduc.github.io/misc/coding-system-rebuild/) for
what the whole system is and how to try it.

## Restored skill credentials

Credential-consuming launchers use named, compiled profiles with fixed
skill-specific authorities:

- `~/.config/ai-agents-skills/axiom-axle.env` projects only `AXLE_API_KEY`.
- `~/.config/ai-agents-skills/lean-explore.env` projects only
  `LEANEXPLORE_API_KEY`.
- `~/.config/ai-agents-skills/research-digest.env` and
  `~/.config/ai-agents-skills/submission-venue.env` project only their declared
  metadata-service keys.
- `workspace/.config/ai-agents-skills/zotero-secrets.json` projects only Zotero's
  explicitly declared keys.
- `workspace/.config/ai-agents-skills/calibre-secrets.json` projects only
  `GDRIVE_CREDENTIALS` and `CALIBRE_GDRIVE_FOLDER_ID` from JSON.

Those launchers enter `/usr/bin/python3 -I -S -B` before loading any skill or
third-party import. The single managed `skills/_load_skill_secrets.py` rejects
relative, linked, oversized, non-owner-private, malformed, duplicate, and
out-of-scope inputs. It rebuilds the child environment from a small allowlist;
ambient provider credentials, Python startup variables, selectors, and future
unknown credential names do not cross the boundary. Its CLI accepts only a
compiled profile name: callers cannot select another authority, projection,
Python script, or import root. The retired shared loader
selectors `AAS_SKILL_SECRETS_FILE`, `AAS_SECRETS_FILE`, and
`OPENCLAW_SECRETS_FILE` are not accepted by these entrypoints.

Calibre and vnthuquan have no shared-secret compatibility fallback. Their
delivery handoff is a data-only queue request and receives no delivery or
Remote Bridge credential pointer.

SMTP and OpenPGP credentials remain host-only. Every real sandbox email send
uses an exact, one-time approval in `$OPENCLAW_HOME/email-approvals/policy.json`;
the OpenClaw launcher routes this unconditionally rather than trusting a caller
environment marker, and the sandbox receives no SMTP or key authority. Unsigned
local previews scrub SMTP, recipient, signature, signing, and identity defaults.
The approval file is initialized deny-all, consumed before delivery, and excluded
from backup so a restored approval cannot replay. File-delivery credentials
are never exposed to a workspace launcher. `send_file.sh` is an untrusted,
queue-only producer; reviewed service installation first derives a minimal,
channel-specific host authority from canonical owner state, and the consumer
requires an exact per-channel target in
`delivery_policy.allowed_targets`. It accepts files only from Zotero staging,
Calibre staging, VNU eOffice's bounded downloaded-document directory, or
`workspace/data/exports`, snapshots the approved descriptor
into an owner-private host spool, and sends the still-open spool descriptor.
Telegram uses fixed `/usr/bin/curl`; captions and chat identifiers use
`--form-string`, and only the document is a file form. Other channels use the
install-attested OpenClaw runtime against that channel's read-only projection.
No delivery worker can read the full OpenClaw state root.
`AAS_FILE_DELIVERY_SECRETS_FILE` and `OPENCLAW_BIN` are ignored.

### Portable file-delivery policy

The portable host authority is
`$OPENCLAW_HOME/file-delivery-policy.json`, with schema
`openclaw.file-delivery-policy/v1`. It contains the `delivery_policy` object
only; it never contains a bot token. The public
`config/file-delivery-policy.json.template` is an explicit deny-all example.
The authority's parent must be owner-controlled and the file must be an
owner-owned, single-link regular file with mode `0600`.

This root file is a separate owner-archive member. The owner archive reads
it directly from the selected OpenClaw state directory, independently of what
the native OpenClaw backup happens to include, and stores it as authenticated
archive authority. Restore therefore quarantines it by default with the other
authorities. The OpenClaw owner archive is the sole backup and restore authority
for this path. An umbrella recovery set embeds that archive and must omit the
same path from its generic secrets payload and generic restore writes; a legacy
duplicate may be compared for exact equality but is quarantine-only input.
There is no workspace policy/token projection.

### Regenerated delivery authorities

Reviewed service installation deterministically regenerates
`~/.local/state/openclaw-bot/delivery-authorities/<channel>/` from canonical
restored authorities; no manual owner provisioning step is required. Each
directory is published with an atomic directory exchange and contains a
mode-`0400` `STATUS.json` using schema
`openclaw.delivery-projection/v1`. A missing or explicitly disabled channel is
`NOT_CONFIGURED`. If a channel is enabled, a missing, linked, overbroad, or
malformed required authority fails installation rather than being relabeled as
unconfigured.

The canonical-to-projection map is:

| Channel | Canonical private input | Regenerated worker authority |
| --- | --- | --- |
| Telegram | `$OPENCLAW_HOME/openclaw.json` plus `TELEGRAM_BOT_TOKEN` in `$OPENCLAW_HOME/secrets.json` | exact raw `telegram/token`, loaded by systemd as one credential |
| Zulip | its channel object in `openclaw.json` plus `ZULIP_API_KEY` in `secrets.json` | one-channel `openclaw.json` plus one-key `secrets.json` |
| Google Chat | its channel object in `openclaw.json` plus the exact referenced `~/.config/openclaw/google-chat/*.json` service account | one-channel `openclaw.json` plus `service-account.json` |
| WhatsApp | its channel object in `openclaw.json` plus `$OPENCLAW_HOME/credentials/whatsapp/default/*.json` | one-channel `openclaw.json` plus a bounded copy of that session JSON set |
| Zalo | its channel object in `openclaw.json` plus `ZALO_BOT_TOKEN` in `secrets.json` | one-channel `openclaw.json` plus one-key `secrets.json` |

`openclaw.json`, `secrets.json`, and the WhatsApp session subtree are owner
archive authorities. The Google Chat service-account file is a separate
canonical private capture owned by the umbrella rebuild. The generated
`delivery-authorities/**` tree is noncanonical, is excluded from capture and
backup, and must be regenerated after restored authority activation. OpenClaw
delivery never reads Remote Bridge state or its Zulip control credentials. A
recognized legacy generated `delivery-authorities/telegram-token` file is
securely removed after the replacement projection is published.

Modern direct restores still require the reviewed human activation token. A
signature-verified `coding-system.recovery-set.v2` restore may instead pass its
signed `owner_data.sha256` through
`--signed-recovery-set-v2-owner-sha256`. The component binds that digest to the
exact no-follow archive descriptor used for GPG decryption and requires the v5
archive runtime version to match. Legacy archives can never use this path.

`~/.openclaw/secrets.json` remains the OpenClaw host authority for gateway,
model-provider, channel, and Moltbook credentials. It is deliberately separate
from the bounded skill authorities and is never projected into a sandbox. A
standalone fresh install therefore keeps the host provider/channel fields in
`config/secrets.json.template` for host-side SecretRefs only.

## Per-agent model authentication

OpenClaw 2026.7.1-2 reads provider profiles from
`agents/<agentId>/agent/openclaw-agent.sqlite`; legacy `auth-profiles.json` is a
migration input only. `backup.sh` never changes live authentication state:
existing canonical databases are snapshotted as-is, while supported legacy
`auth-profiles.json`, `auth-state.json`, `auth.json`, and `models.json` remains
authenticated quarantine input. Materialization is a separate explicit helper
operation, or occurs inside verified inert restore staging after reviewed
authority activation has been authorized. Conflicting model credentials receive deterministic
profiles and state ordering preserves which credential was active. Unsupported
sensitive headers or executable SecretRefs fail closed; redaction placeholders
are never promoted. The conversion is offline, idempotent, prints only counts
and digests, and normalizes only safe same-tree legacy agent aliases. OpenClaw's
native `backup create --verify` (on `/usr/bin/node`, or on the sealed Node of a
coding-system restore) then snapshots canonical
`*.sqlite` state with `VACUUM INTO`. The v5 owner helper snapshots persistent `*.db` and
`*.sqlite3` files with SQLite's online backup API, rejects sidecars and unknown
SQLite filename forms, and excludes regenerable cache directories. It then
builds a link-free, non-executable, data-only encrypted archive. Root plugins,
extensions, hooks, skills, browser runtime, workspace Git metadata, scripts,
runtime control, and other executable trees never enter the owner archive.

The native snapshot of `state/openclaw.sqlite` is also retained because it is
OpenClaw's global, credential-capable state database. The owner helper requires
its v1 global-role metadata and auth/device/push credential table shape, stores
it below authenticated archive-authority quarantine, and never substitutes a
live file copy for OpenClaw's transactional snapshot.

Archive configuration, credentials, schedules, task/flow definitions, and
other executable authority are stored only below the authenticated archive's
embedded quarantine payload. Restore keeps them quarantined by default. A
reviewer may activate modern archive authority only with the exact
`ACTIVATE_REVIEWED_ARCHIVE_AUTHORITY` confirmation. The signed recovery-set v2
path auto-activates the digest-bound modern owner authorities needed for
one-command closure: configuration, credentials/SecretRefs, device/identity
state, schedules/tasks/flows, and file-delivery policy. Canonical per-agent
SQLite is restored as data and then structurally verified. Legacy per-agent
auth/model JSON remains quarantine-only and can never become active.

Action queues (`send-queue`, `job-queue`, `manim-queue`, and `email-queue`) are
excluded from the archive. On restore, every pre-existing active queue is copied to
`recovery-quarantine/action-queues/<provenance-id>/` inside the private
candidate with a SHA-256 inventory; newly active queues are empty and mode
`0700`. Nothing replays automatically. Review approval and replay are separate
operations requiring, respectively, exact `REVIEW_QUARANTINED_ACTIONS` and
`REPLAY_QUARANTINED_ACTIONS` confirmations. Replay locks the owner state and
destination queue, copies each pinned source descriptor into private staging,
never overwrites a job, and records prepared/published journal transitions for
crash recovery before removing the quarantined source.

`backup.sh` and `restore.sh` hold a descriptor-anchored exclusive owner-state
lock. Gateway and queue writers hold the same lock in shared mode for their
lifetimes, so a live writer cannot overlap an owner-state transaction.
Telegram, Zulip, Google Chat, WhatsApp, Zalo, SageMath, Manim/TeX, and
SMTP/OpenPGP run as distinct worker units with separate runtime directories,
queue mounts, memory/task/CPU limits, hidden homes, empty capability sets, and
read-only system trees. Each networked delivery unit sees only its own queue,
policy, and exact channel authority. SageMath and Manim have no host network
namespace; the Manim unit additionally sees only its pinned venv, render queue,
export roots, and attested runtime. Scene specs bound
equation count/size, duration, frame rate, resolution, and unsafe TeX primitives;
TeX uses paranoid file-I/O settings and renderer subprocess groups have timeouts.
Restore
decrypts the archive and passphrase through pinned descriptors, executes only
opened root-owned `/usr/bin/gpg` and `/usr/bin/gpgconf` inodes, and gives GPG a
fresh mode-`0700` homedir, `--no-options`, `--no-symkey-cache`, an explicit
`/proc/self/fd/<output>` destination, and a fixed minimal environment. The
scoped agent is killed and its bounded homedir is removed before success. It
then verifies and extracts the same tar descriptor into a private stage, checks
gateway/queue-worker quiescence both before staging and before publish, and
validates DB-first auth before activation. A complete sibling candidate is
published with an atomic directory exchange; the old state remains in a
private `*.restore-rollback-*` directory. Failure before that exchange leaves
the active prefix unchanged, while a crash after it leaves a complete new
prefix plus the rollback tree. Existing prefixes must already be owner-private;
the restore fails closed instead of carrying an exposed tree into rollback.
Restored archive content is never executed. Restore leaves user services
unchanged. Service installation is a separate reviewed operation requiring the
exact `INSTALL_REVIEWED_USER_SERVICES` confirmation; it renders into private
temporary files, rejects linked destinations, rolls back on any write/reload
failure, and treats `systemctl --user daemon-reload` failure as fatal. The
transaction helper has no public source/destination/home arguments: it derives
the reviewed repo service tree and real user-systemd destination, and requires
an inherited descriptor matching this repo's exact installer inode.

Owner backup and restore plaintext is staged only in an owner-private tmpfs
directory under `/run/user/$UID` or `/dev/shm`; ambient `TMPDIR` is ignored.
If neither tmpfs is available, the operation fails unless the operator supplies
the exact, explicit
`--allow-persistent-plaintext-staging ACKNOWLEDGE_PERSISTENT_OWNER_PLAINTEXT`
acknowledgement. That fallback uses a fixed owner-private directory and is
cleaned on exit. Gateway and queue-worker units likewise receive private
systemd runtime directories instead of `/tmp`. Security-sensitive shell
entrypoints run `/usr/bin/bash -p`, use a fixed system `PATH`, and scrub shell,
language-runtime, loader, and Git injection variables; the owner-state-lock
re-exec preserves privileged Bash mode.

Reviewed service installation copies every custom service artifact into an
owner-private, generation-addressed
`~/.local/libexec/openclaw-bot/generations/<sha256>/` tree outside sandbox
mounts. Units execute only its aggregate/per-file/self-attesting launcher; no
systemd service executes workspace code. The generation also seals the exact
Node, OpenClaw entrypoint, package metadata, and version. After service install,
umbrella verification can use these stable component entrypoints:

```bash
/usr/bin/python3 -I -S -B scripts/run_host_command.py health --timeout 10000
/usr/bin/python3 -I -S -B scripts/run_host_command.py cron-export
```

Markerless legacy archives are refused by default. They require both
`--allow-legacy` and isolated `--overlay-only` mode, cannot contain SQLite or
executable members, and never restore `openclaw.json`, `secrets.json`, `.env`,
credentials, identity, devices, or cron authority. Only inert non-authority data
is overlaid from that explicitly accepted legacy format.

The full restore performs an offline structural authentication closure before
publication. It executes neither OpenClaw nor `doctor`, enables no network, and
loads no provider/plugin configuration. All legacy auth/model filename variants
(including case, backup, and dot variants) are quarantined. Canonical SQLite is
opened read-only through no-follow descriptors and checked for integrity,
schema/agent ownership, the pinned v1 primary-store contract, JSON syntax, nested Unicode-normalized redaction
sentinels, and executable (`source: exec`) SecretRefs. Executable SecretRefs
fail closure and remain quarantined; the offline check does not claim provider
resolvability or profile usability. The checker reports only structural status
and counts; it never prints credential payloads or treats ambient environment/
model JSON as proof of portable per-agent authentication. A missing canonical
store is `FAIL` unless `--allow-unconfigured` is explicit; in that mode it is
reported as `UNCONFIGURED`, never `PASS`.
